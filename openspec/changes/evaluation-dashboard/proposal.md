## Why

The dashboard already has a polished 5-tab frontend (Portfolio, Positions, Calibration, Operations, Costs & Ops) with Plotly.js charts, PicoCSS dark theme, and 30-second auto-refresh. But simulation results and backtesting insights are trapped behind CLI commands. There is no way to visually explore the relationships between model performance, market categories, volume tiers, and temporal effects. The central question — "where does the agent add alpha?" — requires interactive scatter plots, heatmaps, and drill-down tables, not terminal dumps. The existing `analysis.py` functions already compute the data; we need API endpoints and new dashboard tabs that integrate into the existing UI.

## What Changes

- Add two new tabs to the existing `static/index.html`: **Evaluation** and **Hypotheses**, following the established tab pattern, dark theme, Plotly.js charting style, and auto-refresh behavior
- Extend `DashboardDB` (or add a parallel `BacktestDB` wrapper) to support read-only access to `backtest.db`. The dashboard currently only connects to `polymarket_agent.db`; evaluation endpoints need to read `bt_simulation_runs`, `bt_simulation_trials`, and `bt_markets`
- Add a new route module `routes/evaluation.py` with endpoints that wrap the existing `analysis.py` functions and add new aggregation queries
- Add a new route module `routes/hypotheses.py` for hypothesis tracking data
- Design for information density — these tabs are analytical tools, not monitoring dashboards. Favor dense data presentation: multi-panel layouts, cross-filtering, sortable tables with inline sparklines, and tooltip-rich charts over whitespace and large KPI cards

### New API endpoints (`/api/evaluation/...`)

- `GET /runs` — list all simulation runs with summary stats (agent Brier, market Brier, trial count, cost, model, dates)
- `GET /trials/{run_id}` — per-trial detail with `?sort_by=brier_diff&category=X&volume_tier=Y` filters
- `GET /compare` — agent vs market Brier across runs, filterable by category, volume tier, and model
- `GET /by-category/{run_id}` — Brier scores grouped by market category
- `GET /by-volume-tier/{run_id}` — Brier scores grouped by volume bucket
- `GET /temporal/{run_id}` — trials ordered by resolution date with rolling Brier difference and regime boundary markers

### New API endpoints (`/api/hypotheses/...`)

- `GET /list` — all hypotheses with status, filters, evidence count, confidence
- `GET /{id}/evidence` — evidence records for a hypothesis with linked run data
- `GET /{id}/actions` — active actions generated by a hypothesis

### Evaluation tab (information-rich)

- **Run selector**: dropdown to pick a simulation run or compare two runs side-by-side
- **Summary strip**: compact row of KPIs (agent Brier, market Brier, diff, n, cost, win rate) — not oversized cards
- **Multi-panel layout** (2x2 grid):
  - **Model comparison**: grouped bar chart — agent vs market Brier by run/model, showing progression over time
  - **Category heatmap**: rows = categories, columns = models, cell color = Brier diff (green = agent better, red = market better), cell text = n trials. Click a cell to filter the drill-down table
  - **Volume tier chart**: bar chart with tiers on x-axis, Brier diff on y-axis, annotated with trial counts and confidence intervals
  - **Temporal line**: x = resolution date, y = rolling Brier diff, vertical dashed lines for LLM regime boundaries (pre-GPT4, GPT4-era, etc.), with shaded training-contamination zones
- **Drill-down table** (below charts): full-width sortable table showing individual trials. Columns: question, category, volume, model, agent estimate, market price, outcome, Brier agent, Brier market, diff, edge, cost. Clicking any chart element filters this table. Supports column sorting and text search.

### Hypotheses tab

- **Hypothesis list**: sortable table with columns for title, status (color-coded badges: proposed=blue, testing=yellow, confirmed=green, rejected=red, invalidated=gray), category/volume/model filters, evidence count, confidence score, last updated
- **Detail panel**: clicking a hypothesis shows its evidence records (linked run IDs, Brier diffs, p-values, sample sizes) and any active actions it has generated
- **Status timeline**: small sparkline per hypothesis showing how its evidence has accumulated over time

## Capabilities

### New Capabilities
- `evaluation-api`: Route module serving simulation results from backtest.db as JSON endpoints, wrapping existing `analysis.py` functions and adding dashboard-specific aggregation
- `hypotheses-api`: Route module serving hypothesis data (list, evidence, actions) from backtest.db
- `evaluation-frontend`: New Evaluation tab in `index.html` with information-dense Plotly.js charts, cross-filtering, and drill-down table — integrated into existing dark theme and tab system
- `hypotheses-frontend`: New Hypotheses tab with sortable table, status badges, and evidence detail panel

### Modified Capabilities
- `dashboard-db`: Extend the DB layer to support a second read-only connection to `backtest.db` (via `BACKTEST_DB_PATH`), with graceful fallback if the file doesn't exist
- `dashboard-app`: Register evaluation and hypotheses routers, add backtest DB to `app.state`
- `dashboard-static`: Add two tabs to `index.html`, following the existing tab/refresh pattern and dark theme conventions

## Impact

- New file: `src/polymarket_dashboard/routes/evaluation.py` — evaluation API endpoints
- New file: `src/polymarket_dashboard/routes/hypotheses.py` — hypothesis tracker endpoints
- Modified: `src/polymarket_dashboard/db.py` — add `BacktestDB` class or extend `DashboardDB` for backtest.db access
- Modified: `src/polymarket_dashboard/app.py` — register new routers, initialize backtest DB connection
- Modified: `src/polymarket_dashboard/static/index.html` — add Evaluation and Hypotheses tabs (~300-400 lines of HTML/JS each, following existing patterns)
- Dependencies: No new Python or JS dependencies. Uses existing `aiosqlite`, `fastapi`, Plotly.js (already loaded via CDN), PicoCSS (already loaded)
- The backtest DB is read-only from the dashboard (same `mode=ro` pattern). The agent's collector and simulator can write concurrently via WAL mode
- Evaluation endpoints re-implement queries in async SQL rather than importing synchronous `analysis.py` functions, keeping the dashboard decoupled from the agent package
